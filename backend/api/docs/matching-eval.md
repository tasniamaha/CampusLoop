## Datasets

**Synthetic** (`test/matching/data/synthetic.json`, frozen). Template-generated campus lost-and-found reports (seed 20261114). 80 LOST queries against 300 FOUND reports: relevant matches, hard negatives and distractors.
95 relevant reports in all. Split 40/40 into tuning and test with the same seed.

- Each generated item yields one LOST report (the query) and one or two FOUND reports of the same item (relevant).
- Noise, applied independently to each side: noun synonyms and paraphrased templates, typos, colour words instead
  of the colour field value, missing colour or brand, brand aliases and case variants, a finder recording a
  neighbouring colour, free-text category variants, different wordings of the same place, vague locations, time
  windows, finders reporting days later, and owners whose window starts after the real date.
- Hard negatives: the same kind in another colour, another brand, a look-alike kind (glasses and sunglasses,
  earbuds and headphones), the same item found weeks before the loss, another item at the same place and day, and
  similarly named places (Lecture Hall A and B).
- Labels are true by construction. `dataset.spec.ts` fails if the generator no longer reproduces the committed file.

Query tags: `brand-alias` 5, `brand-missing` 35, `category-differs` 56, `colour-conflict` 13, `colour-missing` 20, `found-before-window` 8, `found-late` 11, `hard-negatives` 55, `location-wording-differs` 65, `multi-relevant` 15, `noun-synonym` 66, `time-window` 28, `typo` 34, `vague-location` 16.

**Hand-written** (`test/matching/data/human.json`). Hand-written campus lost-and-found reports in free-form wording, not produced by the generator: 20 LOST queries against 95 FOUND reports (h-f01 to h-f45 written with the queries, h-f46 to h-f95 added as distractors, several deliberately close to a query). Every query is held out (never used for tuning). 20 relevant reports.
Written separately from the generator in free-form wording, including abbreviations (LH-A), aliases (HP and
Hewlett-Packard, Redmi and Xiaomi), colour clashes (a gold frame in a brown case), typos and a found date before the
owner's window.

Query tags: `brand-alias` 2, `brand-missing` 9, `category-differs` 16, `colour-conflict` 1, `found-before-window` 1, `hard-negatives` 18, `location-wording-differs` 20, `noun-synonym` 14, `time-window` 3, `typo` 1, `vague-location` 2.

## Method

- **Relevance** is binary: a FOUND report is relevant to a LOST query when it describes the same physical item.
- **Ranking** is the list a system actually returns, after its own filtering. A relevant report it drops or never
  considers is a miss: it lowers R@5 and, if it is the only one, sets the reciprocal rank to 0.
- **P@5** = relevant reports in the top 5 / 5. **R@5** = relevant reports in the top 5 / all relevant reports.
  **MRR** = mean of 1 / rank of the first relevant report. Means are over queries.
- Campus and type filters (project.md §7) are applied before ranking, so every pool here is one campus of open
  FOUND reports. All pool reports are treated as open at the same time.

### Systems

- **keyword baseline**: Shared distinct words (3+ letters) in title and description; ties newest first.
- **current matches()**: Production algorithm at a105fd3: newest 100 candidates only, crude weights 35/30/20/15.
- **current, no cap (diagnostic)**: The current scoring over every candidate, without the newest-100 cap: the fair comparison for scoring quality. Not a production system.

## Limitations

- **Not independent.** The synthetic set and the systems are written by the same author, and the noise tags were
  designed alongside the planned scorer features, so synthetic gains (per-tag gains above all) are optimistic. The
  set was frozen before the new scorer was written.
- **Independence in code.** The scorer in `src/` shares no colour, synonym or brand-alias lists with
  `test/matching/`; `src-independence.spec.ts` fails if anything in `src/` imports from it.
- **The hand-written set is the credibility check**, but it has only 20 queries, so one query
  moves its MRR by up to 0.050. Its labels are not yet reviewed.
- One campus, all reports open at once, and no churn: real pools change while a report is open.
- Latency covers in-process scoring only, on one machine.
